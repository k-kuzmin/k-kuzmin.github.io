Карта

Путь задачи и защита на каждом участке

Слева — порядок стадий от issue до мерджа. Справа — что стоит на каждой из них. Первое слово в чипе говорит, чем держится защита: сессия — механика субагента, хук — git до создания коммита, CI — работа на сервере, метка — состояние, живущее вне сессии, человек — разрешение, которое не выдаётся автоматически.

Рубеж 01

Сессия: чего у шага нет, того он не сделает

Определение шага — файл в репозитории. В нём набор инструментов, список разрешённых команд, модель и потолок ходов. Всё это читается до запуска шага и не зависит от того, что модель считает уместным.

чем срабатывает
Набор инструментов — рамка сессии; хук на каждый вызов Bash — проверка команды до исполнения.
что читает
Сам вызов инструмента: имя инструмента и строку команды.
что отбивает
Правку файлов у читающего шага — Edit и Write ему не выданы. Команду вне списка шага — включая вторую команду в конвейере и спрятанную в подстановке.
от чего защищает
От ревьюера, который «заодно поправил мелочь» в проверяемом диффе: такая правка приезжает в PR без ревью, потому что ревьюер её и сделал. И от шага, у которого спросили дифф, а он на всякий случай запустил миграцию базы.

Читающий шаг · ревью корректности

tools: Read, Glob, Grep, Bash
hooks:
  PreToolUse:
    - matcher: Bash
      hooks:
        - type: command
          command: >-
            bash "$CLAUDE_PROJECT_DIR/scripts/step-bash-allow.sh"
            'gh pr diff' 'gh pr view' 'gh pr checks' 'gh issue view'
            'grep' 'head' 'tail' 'pwd'

Пишущий шаг · реализация

tools: Read, Glob, Grep, Edit, Write, Bash
          command: >-
            bash "$CLAUDE_PROJECT_DIR/scripts/step-bash-allow.sh"
            'dotnet restore' 'dotnet build' 'dotnet test' 'dotnet format'
            'git checkout' 'git switch' 'git status' 'git diff' 'git log'
            'git add' 'git commit' 'git push'
            'gh issue view' 'gh pr create' 'gh pr view' 'gh pr edit'
            'grep' 'head' 'tail'
            'bash scripts/rules-sync.sh' 'bash scripts/wiring.sh' …

Разница между двумя определениями — не в тоне инструкции, а в двух строках: Edit, Write и список команд. dotnet ef не выдан ни одному шагу: миграция — решение человека.

Что отбито поимённо

Списка команд мало: у разрешённой команды бывает флаг, отменяющий рубеж уровнем ниже. Такие флаги перечислены отдельно, и отказ на каждый объясняет причину.

Что отбитоПричина отказа, из текста проверки
--no-verify у git commit выключает pre-commit с gitleaks
-n у git commit тот же --no-verify, только короче
--force у git push перезапись истории ветки, которую уже видели CI и ревью, — решение человека, а не шага
--output у git и gh делает из читающей команды запись в файл, минуя набор инструментов
правка меток agent/allow-* это разрешения человека, и снимать их себе шаг не может
подстановка $(…) внутри неё прячется вторая команда, и список разрешённого её не видит
перенаправление вывода это канал записи в обход набора инструментов
перенаправление ввода <(…) внутри запускается команда, которой в списке нет
фоновый запуск результат такой команды не виден ни шагу, ни этой проверке
незакрытая кавычка разобрать команду на части нельзя, а пропустить неразобранное хук не может

Отдельный случай — отсутствие jq, которым хук разбирает вход. Без него отказ получают все вызовы Bash, а не пропускаются молча: непроверенная команда и разрешённая команда — не одно и то же.

Рубеж 02

Коммит: до создания, а не после

чем срабатывает
Два git-хука в репозитории: pre-commit и commit-msg.
что читает
Индекс — то, что коммитится, а не рабочий каталог целиком. И текст сообщения.
что отбивает
Секрет в индексе; заголовок не по Conventional Commits. И отсутствие самого инструмента поиска секретов.
от чего защищает
От секрета в истории. Коммит с токеном не лечится следующим коммитом: значение остаётся в истории навсегда, и чинить придётся перезаписью ветки — а токен к этому моменту уже утёк.

pre-commit · секреты в индексе

if ! "$GITLEAKS" git --staged --redact --no-banner --log-level warn .; then
    cat >&2 <<'MSG'

  Коммит отклонён: gitleaks нашёл секрет или приватные данные.

  Значения в выводе выше отредактированы. Что делать:

    1. Убрать значение из файла. Секреты приходят только из
       IConfiguration: локально dotnet user-secrets, в продакшене
       переменные окружения.
MSG

commit-msg · формат заголовка

CC_PATTERN='^(feat|fix|chore|docs|refactor|test|perf|build|ci|revert|style)(\([a-z0-9._/-]+\))?!?: .+'

# Merge- и revert-коммиты git формирует сам.
case "$SUBJECT" in
    Merge\ *|Revert\ *) ;;
    *)
        if ! printf '%s\n' "$SUBJECT" | grep -Eq "$CC_PATTERN"; then

Исключение для Merge и Revert — не послабление: эти заголовки формирует сам git, и требовать от них формата значит запретить мердж.

Рубеж 03

Сборка: то, что нельзя сломать «на время»

чем срабатывает
Свойства сборки, архитектурный тест среди обычных тестов и порог покрытия в работе CI.
что читает
Код целиком: собранные сборки и их ссылки, отчёт покрытия по строкам.
что отбивает
Любое предупреждение компилятора; ссылку из ядра в адаптер; падение покрытия ниже нижней границы.
от чего защищает
От чистой архитектуры, оставшейся только на схеме в README. Ссылку из ядра наружу ставят «на время»: она проходит ревью как мелочь, а снять её потом стоит рефакторинга. Тест делает это невозможным — и падает у автора, а не через месяц.

Тест · направление зависимостей

IArchRule rule = Types()
    .That().ResideInAssembly(CoreAssembly).As("ядро")
    .Should().NotDependOnAny(
        Types().That().ResideInAssembly(
        ApiAssembly, DataAssembly, /* … */))
    .Because("ядро содержит только порты и модели");

rule.Check(Architecture);

CI · порог покрытия

minimum = float(os.environ['COVERAGE_MINIMUM'])
actual = 100.0 * covered / valid

if actual < minimum:
    sys.exit(
        f'::error::Покрытие {actual:.1f}% ниже границы {minimum:.0f}%. '
        'Границу не двигать — дописать тесты.')

Нижняя граница покрытия — защита от обвала, а не цель. Инструкция «границу не двигать» лежит в тексте ошибки, потому что читать её будет тот, кто как раз собирался её подвинуть.

Рубеж 04

PR: гейт смотрит дифф, а не состояние кода

Это единственный рубеж, который проверяет не код, а изменение. Разница принципиальная: подавление, лежащее в коде давно, гейту невидимо — он ловит только добавленное сейчас. Так и задумано, и цена этого названа в первой записке.

чем срабатывает
Гейт целостности и сверки обвязки — работы в быстрой проверке PR.
что читает
Гейт — дифф против базовой ветки. Сверки — репозиторий целиком: они проверяют инварианты, а не свойства диффа, поэтому идут и на push.
что отбивает
Защищённые пути без метки-разрешения; добавленное подавление проверок; удаление тестов; деструктивную миграцию; правку контракта API. Плюс ссылку на несуществующий файл правил, копию правила вместо ссылки и скрипт, который никто не запускает.
от чего защищает
От зелёного чека, добытого #pragma warning disable вместо починки, — красный чек давит непрерывно, и это первое, что модель пробует. И от правила, размноженного копией: правят одну копию, а работают по другой.

Гейт · подавления

SUPPRESSION_PATTERNS=(
    '\[Ignore(\]|\()'
    '#pragma[[:space:]]+warning[[:space:]]+disable'
    '<NoWarn[>[:space:]]'
    'continue-on-error:[[:space:]]*true'
)

Гейт · защищённые пути

PROTECTED_PATTERNS=(
    'Directory\.Build\.props'
    '\.editorconfig'
    'global\.json'
    # --- Сам пайплайн ---
    '\.github/.+'
    '\.githooks/.+'
    'scripts/.+'
    # --- Правила и принятые решения ---
    '\.claude/CLAUDE\.md'
    '\.claude/agents/.+'
    'docs/rules/.+'
    'docs/decisions/.+'
    …
)

CI · метка как разрешение

env:
  # Метки снимают запрет на защищённые пути, контракт и
  # деструктивную миграцию. Ставит их человек — в этом и смысл.
  GUARD_ALLOW_PROTECTED: >-
    ${{ contains(github.event.pull_request.labels.*.name,
        'agent/allow-protected') }}

Сверка · копия вместо ссылки

# Скользящие окна по COPY_WINDOW слов.
windows() {
    normalize "$1" | tr ' ' '\n' | grep -v '^$' \
    | awk -v n="$COPY_WINDOW" '{ buf[NR % n] = $0
        if (NR >= n) { s = ""
            for (i = NR - n + 1; i <= NR; i++) s = s (s == "" ? "" : " ") buf[i % n]
            print s } }'
}

Метка — это разрешение человека, попавшее в CI как переменная окружения. Правка защищённого пути не запрещена навсегда: она запрещена до того, как человек её разрешил. Снять метку себе шаг не может — это отбито поимённо рубежом выше.

Рубеж 05

Черновик снят: проверяется работающий стек

Тяжёлая проверка идёт не на каждый пуш, а по снятию черновика: она поднимает систему целиком на примерах конфигурации и разговаривает с ней по HTTP.

чем срабатывает
Подъём стека в контейнерах на .example-конфигурации и статический анализ безопасности.
что читает
Живые ответы эндпоинтов, логи запуска и логи после подстановки заведомого секрета. Исходники — анализатором.
что отбивает
Стек, который не встаёт без правок; ответ /health не по форме; эндпоинт, отвечающий без аутентификации; значение секрета, видное в логах.
от чего защищает
От репозитория, который собирается, но не поднимается: у чужого человека docker compose up падает на первом шаге, и портфолио превращается в архив исходников. И от эндпоинта, открытого анонимно, — забыть атрибут дешевле, чем заметить, что его забыли.

Проверка · аутентификация обязательна

- name: Эндпоинты API требуют аутентификации
  run: |
    code="$(curl --silent --output /dev/null --write-out '%{http_code}' \
      http://localhost:8080/api/v1/state)"
    test "$code" = "401" || { echo "ожидался 401, получено $code"; exit 1; }

Проверка · секретов в логах нет

docker compose logs api > api.log
# Ищем значения, а не имена: имя поля в логах законно,
# значение токена или пароля — нет.
if grep -nE '(Bearer [A-Za-z0-9._-]{20,}|eyJ[A-Za-z0-9_-]{20,}\.|Password=[^;$ ]{4,})' api.log; then
    echo '::error::В логах старта обнаружено похожее на секрет значение.'
    exit 1
fi

Проверка ищет значения, а не имена полей: имя Token в логе законно, значение — нет. Правило «токены не логируются никогда» тем самым перестаёт быть пожеланием.

Рубеж 06

Мердж: рубеж, которого сегодня нет

Пять рубежей выше — механизмы. Шестой — нет, и притворяться иначе бессмысленно: страница о механической защите, у которой один из пунктов держится на добросовестности, обязана называть этот пункт.

чем срабатывает
Ничем. Защита ветки не включена, обязательное ревью от владельцев кода — тоже.
что читает
—
что отбивает
Сегодня — ничего. Мердж делает человек, потому что так заведено, а не потому, что иначе нельзя.
от чего защищало бы
От мерджа без человека. Роль «человек обязан посмотреть» сейчас выполняет гейт целостности рубежом раньше: он краснеет на защищённых путях, пока метку не поставил владелец.

Владельцы кода · почему проверка не включена

# Обязательное ревью от CODEOWNERS в настройках репозитория намеренно НЕ
# включено. Причина: GitHub не засчитывает апрув автора PR. В репозитории
# одного человека владелец — единственный code owner, и требование
# «апрув от CODEOWNERS» заблокировало бы каждый его собственный PR
# навсегда. Обойти это можно только правом администратора, то есть гейт
# превратился бы в ритуал, который всегда обходят, — худший вид гейта.

Причина отказа записана там же, где отказ, — в файле владельцев. Это и есть разница между известной дырой и забытой: известная лежит с объяснением рядом с местом, где её ожидают найти.

Границы шага

Все семь определений и один отказ

Выше рубеж сессии показан на двух определениях из семи. Вот все семь — и что происходит с командой, которой в списке шага нет. Шагов шесть, а определений семь: у починки их два.

Из стенограммы прогона Команда «pwd» не входит в список разрешённого на шаге
Перенаправление вывода запрещено: «gh issue view N 2>&1 | head -100»
Шаг Модель Правит файлы Команды
Триаж младшая нет gh issue view · grep · head · tail
План сессии нет gh issue view · grep · head · tail
Реализация сессии да dotnet build / test / format · git · gh pr create · сценарии обвязки поимённо
Ревью — корректность сессии нет gh pr diff · gh pr view · gh pr checks · gh issue view
Ревью — безопасность сессии нет gh pr diff · gh pr view · gh pr checks
Оценка случайного падения младшая нет gh pr checks · gh run view · grep · head · tail
Починка сессии да dotnet build / test / format · git · gh pr comment · gh run view

Отказ видно — поэтому границу правят, а не обходят. После этого прогона pwd выдали пяти читающим определениям, а потолок ходов триажа подняли до двадцати пяти: рамка оказалась уже, чем чтение, которое требуют его же правила. Молчаливое нарушение такой правки не вызывает — оно не оставляет следа.

Предел механики

Где кончается механика и начинается дисциплина

Дыры реализации — те, что видны из фрагментов выше. Каждая известна и ни одна не закрыта надеждой на то, что модель прочитала инструкцию.

  • Список подавлений конечен. Четыре шаблона ловят четыре известных способа. Пятый, ещё не придуманный, пройдёт — поэтому рядом с запретом записан штатный исход: остановиться и написать в PR, что именно не сходится. Остановка с объяснением — нормальный результат, зелёный чек, добытый подавлением, — нет.
  • Команды разбираются до поимённых флагов, а не по всем аргументам. Вторую команду в конвейере и в подстановке хук находит, флаги вроде --no-verify знает по имени. Изобретательное применение разрешённой команды — не находит.
  • Рубеж коммита включается руками. Хуки не подключаются к клону сами: без git config core.hooksPath их нет вовсе. Подстраховка — те же проверки в CI, но в свежем клоне локального рубежа не существует.
  • Копия правила ловится дословно. Скользящее окно в десять слов находит копипаст; тот же смысл, пересказанный своими словами, проходит и расходится с источником молча.
  • Гейт видит только изменение. Подавление, лежащее в коде давно, для него не существует — рубеж защищает от новых, а не от накопленных.
  • Рамка сессии смотрит на команду, а не на путь правки. Хук стоит на вызове оболочки, а файл правится другим инструментом — и защищённый путь для него такой же, как любой другой. Переписать саму проверку шаг может; красным это становится только на PR.
  • Гейт запускается из ветки, которую проверяет. Работа чекаутит PR и вызывает гейт оттуда же, самопроверки целостности у него нет. Дифф, ослабляющий гейт или удаляющий его работу из пайплайна, проходит собственную проверку — а без обязательных чеков отсутствующий чек не отличается от зелёного. Закрывается двумя правками: прогоном версии из базовой ветки и обязательными чеками. Пока не сделано, и последним рубежом здесь остаётся человек.

Полный список того, чего схема не гарантирует, — вместе с ценой каждого рубежа в первой записке.
